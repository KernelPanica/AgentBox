# AgentBox: проект универсальной контейнерной среды

Статус: согласован пользователем, реализация создана; результаты в reports/verification.md. Дата: 2026-11-19.

## Назначение и требования

Локальное приложение для Linux и Docker Compose. После первоначальной
конфигурации одна команда запускает выбранного агента и его сетевое окружение.
Пользователь подтвердил поддержку CLI и графических приложений.
Существующий Claude в `/home/kernelpanica/claude-code`, его контейнеры,
сети, credentials, лаунчеры, systemd и правила хоста не изменяются.

Цели: сменные агенты, сменные VPN, принудительный VPN для всего исходящего
трафика агента, блокировка сети при отказе VPN, отдельное файловое и
графическое окружение. При отсутствии корректной конфигурации запуск закрыт.
Неудача: тихий выход напрямую, доступ к системе пользователя или влияние
на существующий Claude.

## Подходы

1. Отдельная среда агента с виртуальным рабочим столом и VPN-шлюзом.
   Предлагаемый вариант: разделяет недоверенные приложения и сетевые привилегии,
   работает с CLI/GUI и не требует сокетов основного рабочего стола.
2. Агент и VPN в одном контейнере. Меньше компонентов, но смена VPN требует
   пересборки среды и усложняет отделение сетевых полномочий от агента.
3. Только переменные HTTP/SOCKS proxy. Проще, но приложения могут игнорировать
   их; это не удовлетворяет требованию принудительного сетевого выхода.

## Границы обещаний

«Любой агент»: Linux-совместимый OCI-образ по контракту запуска,
с CLI-командой и/или GUI-командой. Приложения только для Windows/macOS,
обязательные GPU/USB/KVM и административный доступ не обещаются.
Адаптер не должен требовать privileged, host namespaces или Docker socket.

«Любой VPN»: расширяемые адаптеры сетевого шлюза. Первая поставка включает
WireGuard, OpenVPN и Xray для VLESS; остальные подключаются по тому же
контракту. Закрытый клиент, которому нужны host networking или установка
службы на хост, не совместим без отдельной разработки. Универсальность
не означает автоматическую совместимость с любым приложением провайдера.

«Агент не знает регион»: скрываем исходный IP от интернет-получателей,
не наследуем host TZ/locale, DNS, имя пользователя, браузерный профиль,
переменные окружения и VPN-секреты. Значения по умолчанию UTC, en_US.UTF-8
и нейтральное имя пользователя. Запрещаем LAN, link-local, metadata и IPv6
в первой версии. Это не гарантия анонимности: текст пользователя, аккаунт,
переданные файлы, fingerprints ядра и сетевые задержки могут раскрыть регион.

Docker использует общее ядро с хостом. Среда ограничивает штатный доступ,
но не обещает защиту от всех уязвимостей ядра. Root/Docker-администратор и
выбранные им образы шлюза входят в доверенную базу.

## Компоненты и сеть

Изолированный Compose-проект на профиль, с отдельными именами, volumes и
подсетями, проверяемыми на пересечение с существующими Docker-сетями.
Пользовательские профили доверенные: их не читает агент.

Агент соединён только с внутренней сетью без внешнего маршрута через Docker.
Его единственный шлюз — доверенный контейнер VPN, имеющий второе,
внешнее подключение. Docker DNS не является разрешённым обходным путём;
используется явно заданный DNS, передаваемый через туннель.

Трафик агента на шлюзе допускается только в tunnel/proxy dataplane.
Внешний интерфейс шлюза пропускает только явно перечисленные literal IP,
протоколы и порты VPN endpoint. Нет bootstrap DNS наружу. Endpoint задаётся
конфигурацией; изменение требует перезапуска после проверки.
WireGuard/OpenVPN используют TUN и маршрутизацию; Xray — прозрачное
перенаправление TCP/UDP. IPv6 блокируется, неподдерживаемые протоколы
не получают прямого fallback.

Правила запрета устанавливаются до запуска VPN и не зависят от его процесса.
На агенте доверенный bootstrap настраивает маршрут и firewall, после чего
необратимо сбрасывает UID/GID и все capabilities, включая bounding set.
Приложение и PID 1 далее непривилегированные. Шлюз получает только
необходимые полномочия; агент не видит его процессы и конфигурацию.

Healthcheck проверяет реальный HTTPS-выход, DNS через туннель и при заданном
expected_exit_ip соответствие IP. Проверка IP не доказывает страну выхода.
Агент стартует только после готовности шлюза. Firewall обеспечивает запрет
прямого выхода даже между проверками; монитор может дополнительно остановить
сессию при unhealthy. Автоперезапуски не должны обходить bootstrap.

Хостовый VPN может перехватывать транспорт нового шлюза: AgentBox обнаруживает
и описывает ситуацию, но не изменяет host routing/firewall автоматически.
В отличие от установки Claude, исключение в маршрутах хоста не переносится.

## CLI, GUI и авторизация

Предлагаемый интерфейс: `./agentbox configure`, затем `./agentbox start`.
Configure интерактивно создаёт приватный профиль; доступен образец для
ручного редактирования. Start выбирает сохранённые агент, VPN и режим.
Дополнительные команды: status, stop, shell, doctor, test, import, export.
CLI поддерживает stdin/TTY, аргументы и сигналы. Одновременно первая версия
поддерживает одну сессию на профиль, несколько профилей независимы.

GUI — собственный Xvfb/оконный менеджер и браузер внутри среды агента,
доступные через noVNC. CLI-профиль также может открыть этот рабочий стол
для авторизации. Браузер и агент используют одну изолированную сеть,
чтобы localhost OAuth callback работал без публикации callback на хост.
Ссылки открываются контейнерным браузером; deep links требуют регистрации
обработчика в конкретном образе агента.

Для доступа к GUI отдельный доверенный UI-relay передаёт только протокол
виртуального дисплея: он имеет изолированное соединение с агентом и
публикует интерфейс только на 127.0.0.1, на свободном порту. Обратный трафик
от агента не должен превращаться в общий TCP-прокси: INPUT/OUTPUT, порт и
направление ограничены. Сеть агента не получает общий интернет через relay.
Управление Docker остаётся в локальном CLI, не в веб-интерфейсе.

GUI защищён случайным паролем на профиль, не записываемым в URL или логи.
Нет автоматического clipboard sync, передачи файлов и host browser OAuth.
Система пользователя не передаёт X11/Wayland, D-Bus, SSH-agent, keyring,
аудио, устройства и каталоги профиля браузера.

## Файлы, образы и секреты

Домашний каталог агента и workspace — отдельные именованные volumes.
По умолчанию bind mounts пользовательских каталогов отсутствуют. Import/export
явно копируют только выбранные файлы; проверяют пути, симлинки и архивы на
выход за границы. Не импортируются домашний каталог и корень системы.

API-ключи агента задаются отдельно от VPN credentials. Не копируются ключи
или профили существующего Claude. Приватные файлы конфигурации имеют mode
0600/каталоги 0700 и исключены из Git/build context. Секреты VPN доступны
только шлюзу. Секрет агента неизбежно доступен самому агенту.
Шифрование секретов на диске в первой версии не обещается.

Образы не получают host env. Произвольные compose overrides не являются
публичным интерфейсом адаптеров. Валидатор запрещает опасные mounts,
privileged, host namespaces, произвольные capabilities и публикации портов.
Образы базовой поставки фиксируются версиями; закрепление digest и
обновления документируются. Runtime root filesystem read-only, writable
пути — volumes/tmpfs; no-new-privileges, seccomp, лимиты памяти/CPU/PID.
GUI-образы сохраняют browser sandbox: глобальный --no-sandbox запрещён.

Первый встроенный образ — нейтральная Linux-среда с терминалом и Chromium,
демонстрационный CLI для проверок и контракт сборки собственного образа.
Адаптер агента описывает image, команды CLI/GUI и требуемые writable paths
из ограниченного набора. Установка конкретного клиента — в его Dockerfile,
без автоматического запуска кода установки на основной системе.

## Проверка и критерии приёмки

Локальные тесты валидируют профили и отклоняют обходы изоляции; проверяют
генерацию firewall, маршрутов, безопасный import/export и обработку сигналов.
Compose config должен проходить проверку без доступа к VPN-секретам в выводе.

Интеграционные испытания запускаются только в ресурсах AgentBox: CLI/GUI,
DNS TCP/UDP, literal-IP TCP, IPv6, Docker DNS, LAN/metadata, отсутствие
host sockets/mounts/capabilities, исходящий IP и готовность VPN. Отдельно:
остановка/падение VPN, недоступный endpoint, рестарт шлюза, запуск агента до
готовности VPN, пересоздание среды и сохранение volumes. Нужен capture на
выделенном uplink с проверкой отсутствия любого выхода кроме endpoint.

Установка Claude не участвует в тестах. Не перезапускаются Docker daemon,
хостовый VPN или ОС. Отсутствие Docker-доступа/endpoint/учётной записи
фиксируется как BLOCKED/NOT_RUN, никогда как PASS. Локальные unit-тесты
не заменяют испытания утечек на работающей сети.

Условия выпуска: после настройки старт одной командой; проверенные CLI и
виртуальный GUI; контракт и образцы адаптеров; подтверждённый kill switch
на испытанном VPN; явная матрица статуса для каждого адаптера. Неиспытанные
адаптеры помечены экспериментальными. README на русском с запуском,
диагностикой, обновлением, удалением только своих ресурсов и ограничениями.

## Решения, оставленные реализации

Версии базовых образов, desktop/noVNC реализация, формат профиля,
конкретные нейтральные подсети/порты, структура Python CLI и тестовый runner
выбираются при составлении плана. Любое решение сохраняет границы выше.
Изменение этих границ требует пересогласования.

## Основания

Из установки Claude заимствованы принципы двух сетей, endpoint allowlist,
проверки реального выхода, необратимого сброса capabilities и fault-тестов.
Её конфиги и credentials не копируются. Для GUI предлагается собственный
дисплей вместо существующего host Wayland forwarding.
