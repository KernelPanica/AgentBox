# AgentBox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build a configurable CLI/GUI agent sandbox with pluggable VPN gateways and a fail-closed network.

**Architecture:** Python standard-library CLI generates fixed Compose topology from a strict JSON profile. Internal agent network, endpoint-restricted gateway, and a localhost-only display relay separate agent code from host resources.

**Tech Stack:** Python 3.11+, Docker Engine 28+ / Compose 2.33.1+, Debian 12, nftables, WireGuard, OpenVPN, Xray, Xvfb, TigerVNC, noVNC.

**Spec:** docs/superpowers/specs/2026-11-19-agentbox-design.md

## Global Constraints

- Existing Claude files, services, containers and host routing/firewall are untouched.
- CLI and GUI are supported; start after configuration is one command.
- No host home, desktop sockets, Docker socket or host namespaces in agent.
- VPN failures never create a direct fallback; no external bootstrap DNS.
- UTC/en_US.UTF-8; IPv6 and LAN/metadata denied; VPN secrets only in gateway.
- Unrun runtime checks are NOT_RUN/BLOCKED, not PASS.

## Review Focus

- VPN configs with executable directives: rejected before container startup.
- Agent-created symlinks and archives: import/export cannot traverse host paths.
- Docker resolver, private destinations and raw sockets: cannot bypass VPN.
- Interrupted startup and gateway recreation: no partially open network.
- GUI relay compromise: no route from agent into management network.
